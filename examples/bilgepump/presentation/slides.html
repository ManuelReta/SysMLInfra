SysML v2 as the Engineering Single Source of Truth
Today — JSON Exports

Each tool exports parameter values as JSON.
Copilot agents read them and emit SysML v2 bind statements.
Examples: pumpA.flowRate = 0.025 from CFD,
efficiency = 0.82 from Simulink.

Future — Live MCP Feeds

Model Context Protocol (MCP) servers will let each tool
push parameter updates directly into the SysML v2 model
without manual export — closing the loop in real time.

🔗
The Centre Node
One SysML v2 project UUID on the public SST API is the version anchor for all disciplines. Structural, safety, reliability, and simulation data share one parametric model and one controlled vocabulary. Any team queries the same endpoint — no reconciliation required.
Standardised Language

SysML v2 is an OMG standard. Every part def, attribute def, and requirement def is machine-readable and tool-independent.

Parametric Analysis

Each analysis def binds exact numeric values from tool outputs and evaluates physics constraints —
no manual number-passing.

Traceable to Standards

Every requirement carries a source-doc reference (SOLAS, MARPOL, DNV, IEC). Every bind value carries a source-tool annotation.

Architecture: 6 engineering tools feed parametric values IN. | SysML v2 evaluates assertions and outputs SATISFIED / VIOLATED evidence. | One model. One truth. Every discipline.

Parallel Evidence Streams
STPA — Hazard Analysis

5 Unsafe Control Action (UCA) requirement defs derived from STPA-BPS-002. Each asserts a controller timing or sensor validity constraint. Nominal positive test: all 5 SATISFIED.

FMEA — Failure Mode Analysis

4 negative-test analysis defs inject fault values (sensor stuck-at-zero, pump cavitation, controller hang). RPN table: 5 of 8 modes exceed action threshold 100. System MTBF ≈ 507,000 years (parallel redundancy).

UQ — Uncertainty Quantification

N=10 deterministic parametric sweep (±1σ, ±3σ, combined extremes) on flow rate, efficiency, and pipe loss. Result: 9/10 SATISFIED · 1/10 VIOLATED (combined 3σ extreme — engineering action flagged).

Traceability chain: every model element carries a sourceDoc reference to the originating standard or tool export. lib/traceability.json maps all elements to source documents. The TraceabilityAgent gates the VerificationAgent — no phantom elements allowed.
